# Edit — `edit-studio/`

Create section of UGC OS. This file loads when Claude works with files under `src/apps/edit-studio/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Download + setup page for the `/video-editor` skill (script + voiceover + B-roll in → finished captioned 9:16 ad out, edited locally — no kie.ai involvement). Hero is a hover-animated ivory folder (`SkillFolder.tsx`, orange glow, work-cards rise out on hover) that downloads `public/video-editor.skill` (keep that copy in sync with the source skill); beside it, a 4-step setup card in the ApiKeyGuide style — **one line per step**, no reassurance paragraph and no second Claude Code link (step 1 is already one); the card is read once and in the way every time after. It sits on the bare **`AppBackground` gradient**, the same one the Dashboard and every other page shows — the shared starfield the two full-page screens used to wear is gone (September 2026, see the Dashboard row) — and the setup card is still cut from the same glass as the Dashboard's widgets (translucent fill + backdrop-blur, white in light mode) rather than a flat tinted panel. Slug `/edit`; crab: Snips · Editor (clapperboard).

**On a phone the reading order is not the desktop one.** Desktop is two columns — folder left, title + benefits + setup card right — and it stays that way. A phone gets one column in the order a stranger needs it: the **title** (what this page is), then the folder and its Download button (the thing to take), then the benefits and the steps. That's done with explicit grid placement (`md:col-start-*` / `md:row-start-*`) rather than a second copy of the header, so the two orders can't drift. Two more phone-only details: the page root takes `overflow-x-clip`, because the folder's halo is a 135%-wide radial glow that hangs past both edges and was scrolling the whole page ~20px sideways; and the pop-cards fan out on `group-active:` as well as `group-hover:`, since touch has no hover and the folder was otherwise a still picture there — a tap plays the fan while the download starts, which is the only confirmation a touch member gets.

## Two agents, one skill

The skill runs in **Claude Code** and in **Codex** (where a member can put GPT-6 Astra behind it), and the toggle in the setup card's header is the whole switch. The bundle itself is agent-neutral by construction — `SKILL.md` is ffmpeg, python and shell — so the only thing v4 had to change inside it was the two steps that said *"view the frames with the Read tool"*: a tool name is an instruction only one host can follow, and the work (look at the JPEG, don't guess from the filename) is what both can. **A new step that needs the agent to LOOK at something says so in those terms**, never by naming a tool.

Everything else lives in `agent.ts`, because the differences surface in three places at once:

- **The steps.** Codex takes five to Claude's four, and the asymmetry is correct rather than an oversight: its skills folder is a place you put a file rather than a dialog you upload one to, and the model is the member's own pick (`/model` → GPT-6 Astra) where Claude Code's isn't part of setting a skill up.
- **The filename.** One archive under two names — the anchor's `download` attribute renames it on the way out, so Codex gets `video-editor.zip` (macOS won't unzip an extension it doesn't know) without a second 45 KB copy of identical bytes in `public/` to keep in sync.
- **The prose brand** (`AGENT_BRAND`, "a **Claude** Skill"). The toggle names the tool you install into, prose names the skill's flavour; conflating them gets you "a Claude Code Skill".

**What does NOT follow the toggle is the folder.** The big tile is ours in both modes (the editor crab) and the pocket wears `SKILL_NAME` — `/video-editor`, in both modes, because it is the skill's NAME and not a command line (Massimo's call, September 2026; it also stops the art flickering between two words as the toggle moves). Which assistant you're setting up in is said by the **sticker** instead: the model picker's own mark from `components/providerMarks.ts`, in its brand colour on a white disc, stuck bottom-left — the one corner nothing else uses, since the version badge owns the top-right and the icon and name run down the middle. Brand-coloured rather than the picker's flat ink because this is one mark on artwork, not a column of a dozen down a panel edge. `providerMarks.ts` was extracted out of `ProviderLogo.tsx` for exactly this: a mark drawn somewhere that isn't a picker row. **`AGENT_COMMAND` is what the member TYPES**, and the last setup step is the only place it appears — so the folder reading `/video-editor` while a Codex member types `$video-editor` is deliberate, not drift.

The choice persists per browser, like the seen-version: the skill is installed into one setup on this machine.

## Shipping a new cut of the skill

The skill is a **file the member installs by hand** — it never auto-updates, and nobody reopens a download page they've already used. So a new version has to announce itself. Bump `SKILL_VERSION` in `stores/skillUpdateStore.ts` and, in the same commit: replace `public/video-editor.skill` and update `SKILL_FILE_SIZE` **and `WHATS_NEW`** in `EditStudio.tsx`. The bundle is repacked from the source skill (`UGC Ad Editor/.claude/skills/video-editor`, which the shipped zip must match file-for-file) with ordinary deflate — `zip -r -X`, not `-0`; storing it uncompressed doubles the download for nothing. Until Edit is opened once on that version, the dock tile carries a red badge dot (top-**left**, because the crab peeks out of the top-right on hover) and the folder wears a "New update · vN" sticker instead of the quiet "vN" one.

**The badge is the announcement and `WHATS_NEW` is the one line explaining it**, in the sticker's own orange under the Download button — and it renders **only while `fresh`**. The standing rule was that nothing at all went on the page, and it was about copy a member reads once and steps over on every visit after; a line that is gone the moment Edit has been opened on this version can't become that, and a member already on vN has no reason to be told what vN was. The button still stays "Download Skill", and this stays ONE sentence — it is a notice, not a changelog. Seen-state is per browser in localStorage, never cloud-synced — the skill is installed into a Claude Code setup on one machine, so "already got it" is a fact about the machine, not the account. `EditStudio` reads `fresh` once on mount and marks seen in an effect, so the badge can't vanish out from under the member reading the page it's on.
