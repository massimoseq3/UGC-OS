# Flow — `flow/`

Automate section of UGC OS, and the one app that makes nothing of its own. This file loads when Claude works with files under `src/apps/flow/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md). The build spec is the Claude Doc "UGC OS Flow: Build Spec"; this file records what the code settled on and why.

## Job

A canvas where each block is an existing app — Characters, Scripts, Voiceovers, B-Roll, Playground, the Ad Analyzer, Outliers, Edit Pack, and Scene Clips (Playground filming a scene script one clip per scene) — plus four helpers (Bank, Image, Text, Batch) and a Note, wired so one run makes a batch of ads. A member meets it on **Flow Home** ("Start a Flow": the Describe It bar under the title, then Templates From the Channel, then Your Flows beside Make a Flow From Your Work, with a blank canvas the last card of Your Flows — a member who has never seen a node editor must be able to run a template without opening one; the layout is the prototype's Flow Home artboard), runs a flow as a form in **Run View**, and opens the canvas only to change something. Phones get Run View and nothing else: editing the canvas stays on a computer (`useIsDesktop` in `Editor`).

**Batch is the member-facing name of the `list` kind** (renamed September 2026). The kind id stays `list` — saved flows, templates and Describe It key on it — so a rename is `KINDS.list.title` and the copy, never the id.

It is an **optional app, OFF by default** (`OPTIONAL_APPS` in `stores/appVisibilityStore.ts`, Settings → Experimental), and in **private beta**: `BETA_APPS` in the same file shows it only to the operator — an admin, or a build with no accounts (local development) — whatever the switch says, and the Settings switch itself renders only for them. A member gets no tile, no route, no switch and no tile entries. It is a view gate, not a lock (a member faking `is_admin` in their own browser reaches a canvas that spends their own key on their own rows); opening Flow to members is taking `'flow'` out of `BETA_APPS`. Hiding it takes its dock tile, its pinned flows' tiles, every tile's How It Was Made / Save as Flow entry (`components/FlowLineageItems.tsx`) and the boot-time run resume (`App.tsx`) with it; nothing is deleted. Dock group **Automate**, after Edit, where the production line ends. Accent cyan `#0891B2` (`--color-flow-*`), the one hue the dock didn't already use.

## Layout of the code

- `engine/` — `catalog.ts` is the block set: typed ports, which output types each input `ACCEPTS`, sources, defaults. `graph.ts` answers wiring questions (`canConnect` returns the refusal as a sentence). `plan.ts` turns a graph plus what's already made into instances, counts and credits. `layout.ts` is Tidy and the layout for graphs nobody placed. `sceneShots.ts` reads a scene script into the clips Scene Clips films. Those five and `hash.ts` are pure and unit-tested (`npm test`); the plan reads the world only through the `PlanDeps` it's handed. The two deps read stores: `held.ts` builds the values a Bank / History / Image / Text block holds, and `cost.ts` prices one instance with the runners' own `estimate` where a runner has one and the registry's `estimateCredits` where it doesn't. `sceneClips.ts` builds a Scene Clips scene's Playground request (prompt, references, fitted length) for the price, the window and the run alike.
- `store/` — `flowStore.ts` (the open flow, edits, undo, selection, the lineage window) and `blocks.ts` (new blocks with each app's defaults, batch slots, row ↔ doc).
- `run/` — `runtime.ts` (the scheduler, run records, reviews, resume), `executors/` (one per runnable kind, each calling its app's runner) and `edits.ts` (a script rewritten by hand in the flow — see Reviews).
- `templates/` — the `.ugcflow` format and its validator (`io.ts`), the static gallery (`gallery.ts`, reading `public/templates/`), and Describe It / Ask Flow (`describe.ts`).
- `lineage/` — Save as Flow and How Was This Made: `trace.ts` walks recorded parents, `saveAsFlow.ts` turns the walk into blocks, `faces.ts` is how a traced row reads on screen.
- `components/` — `FlowHome` (+ `FlowDiagram`, the mini block diagram on template and flow covers), `Editor` (the header band and the full-width canvas; `EditorHeader` carries Run Flow, Test With 1 and the run summary), `Canvas` (React Flow), `BlockNode` (+ `node/`: each kind's face, and the helpers edited on the canvas), `window/` (a block open in its app's own window — see Block windows), the canvas's controls (`ContextMenu`, `AddBlockMenu`, `WirePeek`, `FlowHelp`, `keys.ts`, `scenesAdvice.ts` — see Canvas), `panels/` (what's left of the old settings column: Run View's `FlowPanel`, the bank / history `Picks`, `StopButton`), `RunView`, `ReviewModal`, `TemplateSetup`, `DescribeIt`, `AskFlow`, `LineageModal`, `FromYourWork`.

## Blocks call the apps' runners, never their own generation

Every executor names a Phase 0 runner (`utils/blockRunner.ts`): `voiceRunner`, `scriptRunner`, `characterRunner`, `playgroundRunner`, `brollStillRunner` / `brollClipRunner` plus B-Roll's row-free storyboard, `adAnalysisRunner`, and Outliers' `searchOutliers`. That is the whole point of Phase 0 — a Flow block and the app it stands for cannot drift into two ways of making the same thing, and every row a block writes lands in that app's own history, counted in the usage ledger, stamped with `flowId` / `flowRunId` / `flowBlockId` and its `parents`. **A new block kind gets a runner in its app first**; an executor that talks to kie directly is the thing Phase 0 exists to prevent. Model picks are the block's own (`settings.modelId`, a `ModelPicker` with `persist={false}` so choosing in a block never moves the app's own pick), falling back to the app's pick, then the registry default. Scripts and the B-Roll storyboard write with each app's own chat model — `ScriptRunInput` has no model slot.

## Block windows

**A block opens in its app's own window, never in a column beside the canvas** (September 2026, Massimo's call: the apps' UI is built and familiar, and the canvas gets the whole width to show the run). Double-click, Enter, the ↗ in its header, or Open on its toolbar. `window/BlockWindow` is the shell — the app's input column on the left working on the block's settings, what the block made on the right (one entry per run, `runs.ts` `blockRuns`), and around them only what a flow has: Generate / From Bank / From History, Pause for Review, Run Field, Turn Off, the Takes strip (what's wired into each input, a × to cut it, + Wire In to add a block that feeds it), and a Generate that runs this block alone. The helpers have no app, so they open nothing: Text, Batch and Note are typed into on the canvas, an Image takes a drop or an upload, a Bank block opens the Bank's own picker.

- **The apps' own panels, bound to the block**: Voiceovers' `SettingsView` + `EditorArea`, Characters' `ControlsPanel`, Scripts' and B-Roll's `InputPanel`, the Ad Analyzer's `ResultsView`, Scripts' `OutputPanel`, Outliers' `ResultCard`. Scripts' and B-Roll's `InputPanel` take an optional **`flow` prop** — a wired field's stand-in card, extra settings, the action label — and do exactly what they did without it. Playground's is the exception, built from the same parts (`SectionCard`, `RefGroup` tiles, `PromptToolbar`, `ConstraintChip`): its `PromptPanel` persists the app's model pick, batches, files into a project and holds inline refs, none of which a block has.
- **Tier `z-[60]`**, like B-Roll's card modal and the voice pickers: every `Dropdown` portals there, so a window above it would paint over its own menus; the bank and model pickers it opens sit above at z-70/80. The canvas's keys stand down while it's open (`keysActive`).
- **A model picked in a window is the block's** (`persist={false}`); it never moves the app's own pick.
- **A reference added in a window lands on the canvas as its own block, wired in** — an upload an Image block, a bank pick a Bank block — never as an inline ref on the block. The canvas stays the one picture of what feeds what, and export's no-picks rule holds with no second path to police. New blocks land on a free spot (`layout.ts` `freeSpot`).

## The run engine

- **A block runs once per trace-compatible combination of its inputs.** Every value carries a `trace` (which block made it, in which run and item); two values from the same upstream block but different items never pair. That is what makes an Edit Pack pair each ad's clips with the same ad's voiceover instead of multiplying every voiceover by every clip set. Required inputs lead a combination; optional ones join it rather than splitting it; an input that takes many (`many: true`) rides with every run. `plan.test.ts` holds the cases — read it before changing `combinations`.
- **Values not made yet are placeholders** (`pending: true`, with a size hint), so everything downstream of an unfinished block is still planned and PRICED — a Scripts block that hasn't run yet still prices the voiceovers after it, at the length its settings will write. The plan is the one source for the canvas counts, every block's estimate, the wire badges and the Run button; nothing counts on its own.
- **Results are cached per instance**, keyed by `fingerprint(kind, generation settings, input value keys)`. `generationSettings` leaves out what doesn't change the output (a batch's count, list entries, keys starting `ui`), so adding a fifth face re-runs one slot rather than all five. A block re-runs only what's missing or changed.
- **Batch blocks come in two shapes.** Characters and Batch are per-slot: each face is its own generation, so a run makes only the slots that are on and empty. A **Change** wired into Characters (a Batch of them: one variant per audience) is the edit modal's instruction: with a Reference Photo it edits that picture through the runner's `edit` path, the form unread, and names the face "Maya · Asian-American" (`variantLabel`); with no picture the plan blocks it. Scripts and Outliers fill every slot in ONE call, and record the `slots` they were asked for — a finished run that came back with fewer hooks than slots is complete, not a reason to pay again. **Scripts' slot count follows the counts Scripts accepts** (`isHookCount` / `isVariationCount`): anything else runs at the default, so the slots must agree or the plan and the run disagree.
- **Test With 1** cuts the whole run to one combination and one item, for a cheap end-to-end check before the real run.
- **An input can be typed into its block instead of wired** where the app takes a paste: Voiceovers' and B-Roll's script (`inlineText` in `catalog.ts`). The planner hands it on as the input's value only while nothing is wired there, keyed by its text; `scriptText` is left out of `generationSettings`, so a wire makes the typed script irrelevant rather than part of the cache key. Scripts' brief, winning ad and product, B-Roll's product, character and instructions, Playground's prompt and Outliers' search are the same idea the older way — a setting the executor falls back to — and stay that way, since moving them would re-key every cached run.
- **Inputs added in September 2026**: Outliers' Search (a Batch of searches runs one per item), B-Roll's Instructions, Edit Pack's Stills (`many`: a B-Roll block's stills go into each ad's folder beside its clips, as `insert-N`), and Playground's Start Frame and End Frame, on its Video tab only (`insOf` is mode-aware; switching tabs prunes the wires). `playgroundInput` fits resolution, aspect and length to what the picked model takes, and the window shows the fitted values, so a value left over from another tab is never sent.
- **Run Block makes what it reads first.** Run Block (a block's own Generate, Run This Block) remakes every run of that block, and whatever upstream of it isn't made yet runs first, the way Run Flow would — nothing beside it runs. Its price in the window's button and the confirm counts both (`ownRunPrice`). It used to refuse with "Run the blocks before it first", the first wall a member building a flow hit.
- **Run Again** (`fresh`): once nothing has changed, the Run button offers Run Again instead of a dead "Nothing to Run": every block makes everything afresh — new takes from the same settings — and always asks first, since it pays for things already made. What the last run made stays in each app's history. An executor told `ctx.fresh` (Run Again, or Run Block on it) starts over rather than topping up: B-Roll carries on in a prior session ONLY between its phases (`ctx.phase === 'clips'`, or a stills-phase prior when not fresh), since carrying on in a finished one handed the old stills straight back. **Forcing is once per press**: the scheduler passes the plan `made` (every run this run already finished), so a block that comes round twice in one run (B-Roll after its review, a run resumed after a reload) never remakes and re-pays what it just made. B-Roll's `keep` lives only between its review and its clips phase; a new session animates every card.
- **What a Scripts block's wiring decides is written on its settings** (`graph.ts` `settleScripts`, run by every edit and every created flow through `shapeBlocks`): a winning ad wired into Source makes it a remix, and the ad's Scene Prompts (or a Scripts block writing scenes) wired in make it the scene-by-scene rebuild (`sceneRemix`), which writes ONE take, so it has one slot. Without that, a fresh Scripts block wired to an ad showed ten hook slots for a run that writes three takes, and priced it that way.
- **A partial failure fails the instance, with the count.** B-Roll with 5 of 35 clips missing used to finish green and ship short packs; now it fails its run ("5 of 35 clips didn't come back…") and keeps every card that landed in its session, so Run Flow remakes only the missing ones. Scene Clips fails only when a scene has no take at all; a missing extra take is filled by the next Run Flow.
- **Reviews pause the run** (`review: true`): the block's results open in `ReviewModal` and only the kept ones run on. B-Roll's review sits BETWEEN its two phases — stills first, then clips for the stills you keep — so no clip is paid for before a still is approved. Review Later leaves it waiting on the block. A review opens only while Flow is the app on screen (the editor stays mounted behind other apps, and a review opened over Scripts was closed as Review Later on the way back), and `ReviewModal` is keyed on its block, so one review's picks never carry into the next. An items review decides only the items it SHOWED: a Test With 1 that made one face of four leaves the other three on for the full run. A Scripts or Characters block that made SEVERAL runs (a face per audience, scripts per product) is reviewed run by run under each run's name: its picks are each run's `keep` (a run with none kept is `off`), and turn no slot off. A review that listed only slot 1 of the first run hid every other run's.
- **Scripts are edited where they're reviewed** (`run/edits.ts`): in Pause for Review (Edit on each take or hook) and in the Scripts window (Scripts' own in-place editing, bound to the block). The edit lands on the block's RESULT (`InstanceResult.edits`, by take index) — the history row keeps what the model wrote — and every item cut from an edited take gets a new key, so what was made from the old words runs again and nothing made from the untouched takes does.
- **A block that fails hands on nothing in place of what it didn't make** (`settled`), so the rest of the flow finishes and the failure is one Retry away.

## Scene Clips

The talking-head ad from the channel, as one block: the loop done by hand in Playground — paste scene 1 with the voice profile on the end, set the seconds to the scene, attach the character (and the product when the scene shows it), generate, repeat — for every scene of a scene script, through `playgroundRunner` (Phase 0: every clip lands in Playground's history). `engine/sceneShots.ts` reads the script with Scripts' own parsers (`sceneParsing.ts`), so a scene here is a scene card there.

- **Each clip is as long as its scene, never shorter than its lines** (the timecode, stretched to `secondsToSay` of the spoken words, 4–15s), snapped UP onto the model's ladder so the lines fit; a scene past the model's longest clip is flagged in the window before anything is spent. Rushed dialogue and 30-second one-shots are the two failure modes the channel names.
- **The prompt is the look, the scene, the rules, then the voice profile** — Playground's Voice box contract. The master blocks come off the script; Rules for Every Clip defaults to "No captions, subtitles or text on screen." **The product photo goes only into scenes that name `[PRODUCT]`** (a script that never marks it shows it everywhere). **Continuity** films scene 1 first and hands its opening frame to every later scene as a reference. A plain script (a hook) is one clip, wrapped as the character saying it to camera — a bare sentence is not direction.
- **Match Voice & Look** (`many`, so it never multiplies runs) lends another scene script's voice profile and look to clips whose own script has none: hooks filmed in the voice of the body they're cut in front of. Edit Pack's **Body Clips** input appends one shared set of clips to every pack — "Many Hooks, One Body" films ten hooks and the body ONCE.
- **Takes aren't part of the block's identity** (`NOT_GENERATION`): the plan counts the clips a result is missing (`missingClips`, by `scene:take` on each `ClipRef`) and re-runs only for those, priced as their share; the executor tops up from `ctx.prior` unless `fresh`. That is also what makes **Test With 1 film scene 1 only** and the full run film the rest without paying for scene 1 again. Every finished clip is kept in the saved task state, so a reload or a failed scene re-films only what's missing.
- **Pause for Review picks the best take of each scene** (`TakesReview`); the picks are the result's `keep`, and the planner hands on only those clips under a key that names them (`keptTakes`). An ad with no take kept is left out (`off`), not handed on empty.
- **A take still being made keeps its handle**: a run where a take timed out (not a dead task) fails with the finished takes kept in its saved state, so the next Run Flow fetches the take rather than paying for it again.
- **Whether a script arrives with scenes is decided upstream**, which a new member can't know: `scenesAdvice.ts` reads the wiring and, when Scripts will write prose (a transcript remix, a plain write), says so on the block and in its window with the one-click fix (use the ad's Scene Prompts; write it as scenes). An unwritten scene script is priced as scenes (`plan.ts` `sizeHint`).

## Paying once

- **A task handle is saved before its wait** (`ctx.save`, persisted under `ai-ugc-lab:draft:flow:tasks`), so a reload, a Stop or a Retry fetches what kie already made instead of paying for it again. kie has no cancel: Stop stops the WAITING, and says so.
- **A handle is dropped only when the task is dead** (`run/errors.ts` `taskIsDead`: the task itself reported failure). A 401, a network error or a timeout keeps it — the task may well have finished — which is what a stale key on reload used to cost: handles thrown away, the same gens paid for twice.
- **Runs resume from the shell.** `resumeBoot.ts` is the only Flow module `App.tsx` imports: it reads the persisted run list and, only if something was running, lazy-loads the runtime after the local banks are ready. Importing the runtime into the shell would put the whole Flow chunk in the main bundle.
- **Run records are local-first** — the live runs, their task handles, and a log of the last 12 runs per flow (`ai-ugc-lab:draft:flow:runs` / `:tasks` / `:log`). They describe work in THIS browser; syncing them is an open question, not an oversight. Load Run puts a logged run's graph and results back as one undo step.
- **Big runs ask first.** Past 500 credits or 20 generations Run shows the bill and waits; a run the balance can't cover doesn't start.

## Recording Mode

A replay run spends nothing and persists nothing: it is never written to the run list, the task store or the log. Each executor's `replay` reveals the oldest hidden row of its bank, the way its app's Generate does. **An executor with no `replay` refuses in a replay** unless it is marked `realInReplay` — Edit Pack (it only gathers) and Outliers (ScrapeCreators, which the Outliers app itself searches for real while recording). That rule is what stops a new executor billing on camera by forgetting a replay. B-Roll's replay names the session it revealed, so its review shows that session's stills and the clips phase after the review stays in it; a replay that finds nothing hidden skips its review rather than opening an empty one. Flow Home's From Your Work reads each bank through `useVisibleRows`, so filming it never shows a hidden row.

## Templates, Describe It and Ask Flow

- **A template is data, never code**: `flow.json` (+ `assets/` + `cover.jpg`) zipped as `.ugcflow`, and the same JSON on the clipboard for copy/paste. **Export never carries a pick or an asset ref**: a bank pick becomes a field ("Your Product", with the author's own as an example name), an uploaded image travels as a downscaled JPEG under `assets/`, and a product or character picked inside an app block (`settings.productId` / `characterId`) is dropped — the importer picks their own. The gallery files' block positions are laid out for the canvas's current block sizes; re-space them when a block's face grows. `validateTemplate` is the one parser for files, the gallery, paste and Describe It: an unknown block kind stays on the canvas and is skipped (a newer build made it), an unknown model falls back to the default, a wire that no longer fits is dropped, and each change is reported as a sentence. Limits: 60 blocks, 8 images at 2 MB.
- **The gallery is static files** in `public/templates/` (`index.json` + one JSON per template), shipped with the build, in index order. Estimates in `index.json` are written by hand from a real plan (the template with its fields picked, through `shapeBlocks`, `planFlow(...).creditsAll`) — regenerate them when a price moves. They are the most a run can cost: a Scripts review that keeps one of three takes spends a third of it. The scene-by-scene templates from the Aug–Sep 2026 videos — Talking Head Ad, Street Interview, Many Hooks One Body, Same Ad Three Faces — carry their video's `videoUrl`. Each entry's `slug` is its template's `template.id`, and its `version` matches the file's (see Sharing and versions).
- **Template Setup** lists what a template needs, checks the key and the balance, prices the run, and keeps Run grey with the reason until every field is filled.
- **Describe It and Ask Flow** are one chat call each on `CHAT_MODEL_DEFAULT`, well under a credit. The prompt carries the catalog (kinds, ports, allowed setting values), the NAMES of the member's bank rows (never images), and for Ask Flow the flow as it stands. They PROPOSE: Describe It's answer goes through the validator with `described: true` — a block kind the model invented is left out (not kept as "needs a newer build"), and each dropped wire says why. A pick that doesn't resolve becomes a field. Ask Flow's operations are applied one by one, each wire checked by `canConnect`; a new block lands one column right of whatever feeds it, the view moves to what changed, and the result stays on screen with Undo until the flow is edited again. Nothing runs until the member presses Run.

## Sharing and versions

- **Two addresses per gallery template** (`share.ts`). `/t/<slug>` is the PUBLIC page (`public/TemplatePage.tsx`), a route outside `AuthGate` beside the legal pages: what the template runs, what you pick, roughly what a run costs, the video, and **Open in UGC OS** / **Get UGC OS** (Skool). It's the link for a YouTube description, because it has to say something to a visitor who isn't a member yet. It reads the static gallery files and nothing else — no banks, no stores that sync, no key — and a slug that isn't `[a-z0-9-]` is refused before anything is fetched. Copy Link on a gallery card copies it.
- **`/flow/t/<slug>` is the member link**, and it is read at STARTUP (`captureShareLink` in `App.tsx`), because RouterSync rewrites every path under an app to the app's own slug and a hidden app's to the Dashboard. The slug waits in sessionStorage through the sign-in screen (same tab), and the workspace sends it to Flow as the `openTemplate` payload, which opens Template Setup over Flow Home. Open in UGC OS is therefore a plain link, never a router navigation — a client-side hop wouldn't restart the app, and the capture would never see it.
- **A member link switches Flow on**, at capture, with a toast saying how to switch it off. The capture reads the switch as set, not the beta gate (who the viewer is isn't known at startup); for a viewer the gate still hides Flow from, the workspace turns the switch back and says Flow isn't open to members yet. Doing it later, after RouterSync had bounced the path to the Dashboard, would start the URL and the active app chasing each other — the loop RouterSync's own comments describe.
- **Versions.** A flow made from a gallery template carries `template { id, version }`, and a gallery entry's `slug` IS that id. When `index.json` lists a newer `version` (with its `changes` lines), `TemplateUpdateBar` offers it in the canvas and in Run View. Update lays the new version in as one undo step and carries the member's field picks across — by the field's block id (instantiate keeps the template's ids), then by its title; other changes to the blocks are replaced, and the bar says so first. **An undo step carries the template stamp** (`Snapshot` in the store), so undoing an update puts the old version's number back with its blocks; Not Now (`template.skipped`) survives any undo, since it isn't a change to the flow. Bump a template's `version` in BOTH its file and `index.json`, and write its `changes`.

## Save as Flow and How Was This Made

Both read `parents` (`Provenance` in `stores/types.ts`), stamped by every runner. `trace.ts` walks them breadth-first; rows made before stamps existed count the ids their app kept for itself (a script's product, a session's product / character / script, a clip's still) — **only when those still resolve**, since an old id pointing nowhere can't be told apart from one that never meant "made from". Children point at parents, never the reverse, so deleting a parent never takes a child with it; a deleted parent reads as "no longer kept".

Save as Flow rebuilds each step with the settings it used. **The product and character become fields**, so the flow runs again for anything. A script made in Scripts is **written fresh each run** by default (a kept script would be about the old product) or **kept word for word** as a Text block. A Scripts block that writes several gets `review: true`, since the original result used one of them. Typed inputs become Text blocks; an uploaded ad's analysis becomes its transcript; a parent no input can take is pruned along with anything that only fed it. A B-Roll clip starts at its session, which is what was made.

Entry points: Flow Home's From Your Work (the latest six results across the history banks), and app tiles through the `lineage` payload — Playground's and Characters' ⋮ menus, Voiceovers' active row, B-Roll's history cards. Scripts' and the Ad Analyzer's rows don't carry it yet: both rows are tight and their delete positions are deliberate (see their own files).

## Canvas

React Flow (`@xyflow/react`). Nodes and edges are DERIVED from the doc on every render — the doc is the only state, React Flow holds nothing of its own beyond the drag in progress — and a drag commits positions on release, as one undo step. **A block drags from anywhere on it** (no `dragHandle`), so every control inside a block — button, field, drop zone — carries `nodrag`, or pressing it drags the block. Measured node sizes feed Tidy and Ask Flow's placement. Undo coalesces edits to one field inside 1.2s; saves debounce at 700ms and flush on `pagehide`. Keyboard (never while typing in a field, never with a window open, never from inside anything portaled over the canvas — a block's own picker included): Delete, Enter (open the block), ⌘Z / ⇧⌘Z, ⌘C / ⌘V (the clipboard carries template JSON, so a selection pastes into another flow or another member's), ⌘D, ⌘A, Escape. Dropping an image on the canvas makes an Image block (on an Image block, it replaces the picture). **Wiring never needs the 11px dot twice**: a wire let go over a block's body wires in only when one input plainly takes it — an empty one of the wire's exact type, else the only empty one that takes it at all — and otherwise asks Which Input?, because a guess spends: a filled input (wired, or a script typed in) is never quietly replaced; let go over empty canvas, or a dot simply clicked (`connectOnClick` is off; the Handle's own click opens it), it opens What Next? — or What Feeds This?, from an input — listing the blocks that fit. The run controls live in the header band (`EditorHeader`): Run Flow carries its price, and its ▾ opens what the run makes and costs, block by block, with what Needs Attention.

**A block shows what it holds on sight** (September 2026, Massimo's call): a Bank pick, an Image and a result reused From Bank or From History wear a square face (`node/face.tsx`) — a pill naming what's picked, with a chevron-right, never a dropdown's, since it opens a picker or the block's window — over the thing itself as a rounded square as wide as the block, its one output dot on the square's edge in place of a ports row. A character is a 9:16 card, never cropped to a square and never letterboxed: a picked one fills the block's width, and the Characters block's faces are 9:16, two across once there are several; each face keeps its own dot (the right column's on the edge, the left's in the gutter), shown on hover or once wired. App blocks show what they make the same way (`node/bodies.tsx`): the Ad Analyzer's cover, score bars and timed scenes; hooks as cards and full scripts as a stack of pages, one tab per take; the voice and every take playable on the canvas (the app's one transport, no waveform); a filmstrip per ad; the Scene Clips timeline; the result big; the ads Outliers found; a folder per Edit Pack. Before a run each shows the dashed shape of what it will make, so a block barely changes height when it runs — `layout.ts` `estimatedSize` is measured off a finished run, and the gallery templates are spaced for those heights (Bank columns 390px apart, B-Roll 360px under Voiceovers). A list shows its first few items plus any wired on their own, since a wire needs its dot. Every field, button and scrubber in a face carries `nodrag` (a block drags from anywhere on it). The palette's labels are the dock's own (10px, regular weight), under the dock tiles every block wears (`blockMeta.ts`). **Nothing on the canvas runs off its edge**, which clips it: every menu keeps itself inside (`keepInside.ts`, measured after it lays out), and the selection's toolbar slides sideways to stay in and drops below the selection at the top (`SelectionToolbar`).

**Control, the node-editor way** (September 2026, for members who know n8n and members who know nothing): a right-click menu on a block, the canvas and a wire (`ContextMenu`), every row naming its key so the menu teaches the shortcuts; **Tab** opens Add Block (`AddBlockMenu`: every block with a sentence on what it's for and what it takes and makes, searched by name first so "scene" finds Scene Clips); **F2** renames on the canvas; an output nothing reads ends in a **+** that opens What Next?; a wire pointed at or selected shows **See What's on It** (`WirePeek`, every value on it, made or not), **Insert** (a block that takes what it carries and makes what its far end takes, wired both ways) and **Cut** at its middle, raised above the blocks only while shown; What Next? / What Feeds This? list one row per port that fits (an ad's Scene Prompts into Scripts' Winning Ad is a different flow from into its Brief); undo / redo and **How a Flow Works** (`FlowHelp`) sit in the zoom pill; the palette's tiles describe themselves on hover. **The empty canvas asks what the flow starts from** (your product, a winning ad, a character) and **the suggested next block appears from the first block** (a product suggests Scripts, a saved ad the Ad Analyzer), wired to the outputs made for it — never a brief or instructions, which a member types. A block added off-screen is brought into view (`reveal`). React Flow turns pointer events off on a node that can't be selected or dragged; the suggested block sets `pointerEvents: 'all'`, or it can't be clicked at all.

## Payloads

`openFlow` (a pinned flow's dock tile → that flow, in Run View), `lineage` (a tile's How It Was Made / Save as Flow → the lineage window over whatever Flow shows) and `openTemplate` (a member share link → that gallery template's setup). **Flow's consumer is keyed on the payload as well as the app**: both are pressed while Flow is already open as often as not, and then only the payload changes.

## Data

Flows are a bank: `flows` in `bankStore` (`saveFlow` / `deleteFlow`), Postgres table `flows` (migration 0026), in the boot cache and the orphan sweep's lists. **Run migration 0026 before deploying** or every hydrate errors and skips the orphan sweep. A flow row holds its blocks, wires and results (`outputs` — values pointing at the apps' own rows and their media, which the sweep therefore counts as live) plus `template` (id + version it came from) and `pinned`. Deleting a flow deletes the flow only: what it made stays in each app's history.

## Known limits

- B-Roll's history is FIFO-capped at 50, and every Flow B-Roll run is a session, so a big run pushes older sessions out.
- Flow's Playground images, clips and music appear in Playground's All Generations like any other Playground run.
- Outliers blocks spend ScrapeCreators credits on the member's key, not kie credits.
- A Characters run where some faces fail loses those slots' handles; Retry pays for those faces again.
- Deleting a row in its own app purges its media, and the flow's result for it then shows empty — it is still cached, so Run Flow won't remake it; Run Block does. Treating a missing row as unmade was weighed and left out: until the cloud hydrate lands, a row made on another device looks exactly like a deleted one, and a plan that read it that way would offer to pay for it again. There is no "hydrate finished" signal to gate on (`markCloudHydrated` fires at the START of hydrate).

## Testing

`npm test` runs `engine/plan.test.ts`, `engine/sceneShots.test.ts` and `lineage/saveAsFlow.test.ts` (vitest, CI runs it). In the browser, a kie stub that answers `createTask`, `recordInfo`, credit, file upload and streaming chat from `window.fetch` exercises a whole run for free — install it before anything polls, or real kie answers 401 and (before `taskIsDead`) dropped the handles. That stub, with a driver and the scenario runs, is `scripts/flow-harness/` (its README says how): `node smoke.mjs --fast --quiet` must say PASS, and the `probe-*` files assert things like no clip submitted twice across a reload. Reach app state there through `window.__appImport`, never a bare `import()`.
