# Playground — `playground/`

Create section of UGC OS — the dock tile sits between B-Roll and Edit. This file loads when Claude works with files under `src/apps/playground/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Free-form Image / Video / Music — tabs in that order, landing on **Image**, because the loop it's used for is "make a still, then animate it". That loop is one click: an image tile's hover stack (and the preview modal) carries an **Animate** action that switches to Video with the still inlined as the start frame and the prompt that made it seeded in the bar (`handleAnimateImage`), going through the same `promptStash` as a manual tab switch so the Image tab keeps its own draft. Each mode remembers its own model under `playground:<task>[:<mode>]` — Image/Music via `ModelPicker`'s own persistence, Video written by the panel itself since `ModelPickerModal` leaves persistence to its caller; without that write every Image → Video flip reset the pick to the registry default. Prompt bar, mode tabs, model picker, model-aware ref slots + drag-drop (images everywhere; Seedance 2 adds audio/video reference clips; Gemini Omni adds characters / designed voices / a trimmed source clip under a 7-slot quota). `@`-mentions reference Products / Influencers / B-Rolls and auto-attach the asset. Uploaded audio/video refs are memory-only (pruned from the persisted draft — too big for localStorage).

**Image and Video carry a batch count** (`BatchCountStepper`, capped at 4, sharing the **model row** at `size='xl'` + `stacked`): Playground is where a prompt gets TRIED, so a run of one is the wrong unit most of the time. `handleSubmit` snapshots the inputs and plans the run ONCE (`planPlaygroundRun` in `runner.ts`: inferred mode, resolved model, the notices) and then calls an inner `runOne` N times, so every member of the run is identical by construction and each is its own task / tile / history row. **Music is excluded** — Suno already returns a pair of tracks for a single call, so a count there would bill twice for something the API hands over anyway. The count rides in the persisted draft (`PromptPanelState.batchCount`, absent on older drafts, clamped on hydrate). **It sits beside the model, not in the constraint row** (August 2026, Massimo's call): a video model that declares every dimension it has — Seedance's resolution, aspect, duration and audio — already fills that line at 375px, so a fifth pill wrapped it onto a second row and the footer grew 56px on exactly the models with the most to fit. It reads better there anyway, since the count is the one control in that row that isn't a property of the OUTPUT: the four chips describe the clip, this describes the run, and so does the model beside it. `stacked` because at the 58px picker-row height a number and its word side by side float mid-pill, and the word ("clips" / "images") is what keeps a bare stepper on a model row from reading as a nudge on the model itself. Its departure is also why the constraint row is now gated on **`hasOutputSettings`** rather than on `mode !== 'music'` — the stepper used to hold that line open unconditionally, so a model declaring no constraints would otherwise render it as an empty 8px margin over Generate.

**Grey, Generate names what's missing** (September 2026, Scripts' `blocker` pattern): "Write a Prompt", or on Motion Control — where the prompt is optional — "Add a Character Image" / "Add a Driving Video", and no credits pill while it's blocked. The empty history pane's hint is layout-neutral ("write a prompt, then hit Generate"): it said "below", and the prompt is to the left on a desktop and on another tab on a phone.

**The video mode is INFERRED from the filled slots, then reconciled with the picked model in both directions — a run is only refused when the model takes no images at all.** `inferVideoMode` (`runner.ts`) reads the slots (start+end → frames, start → image, refs → reference) and knows nothing about the model; the reconciliation right after it is what makes the two agree. Both directions are real: an image-to-video-only model (Kling 3.0 Turbo) can't take a reference image but can animate it as a start frame, and a **frame-less** model (Seedance 2.5 as it was first registered) has no `first_frame_url`/`last_frame_url` at all and folds every attached image into its reference array — which is exactly what those models' `buildVideoInput` branches already do with a stray frame. Only the first direction existed, so attaching a start frame **and** a reference image inferred `image-to-video`, Seedance 2.5 doesn't declare it, and the run was refused with a toast naming a limitation the model doesn't have — reported as "it said Seedance 2.5 doesn't accept reference images", on a generation that would have run fine. When the mode lands on reference-to-video the frame slots are sent AS references, in shot order ahead of the explicit ones, or the downgrade would trade a false error for a silent drop. **Check `buildVideoInput` before refusing a run over an undeclared mode** — the declared modes say what the model calls its inputs, not whether the pictures reach it.

**A frame and a reference attached together resolve per model, through `mixedImageInputPolicy`, and every outcome is toasted.** There is no universal answer here — the providers designed three different things, and a surface that guesses either drops an input silently or sends a 400:

- **`merged`** (Gemini Omni Flash 1.1, Grok) — both inputs reach the model, so everything is sent and nothing is said, because nothing was traded. Grok gets there with one flat `image_urls` array that has no frame/reference distinction at all; Flash 1.1 keeps real `first_frame_url` / `last_frame_url` fields BESIDE `image_urls` and simply accepts the pair. The policy answers "what happens when both arrive", not "how many fields does the body have" — which is why the two shapes share one value. (Gemini Omni 1.0 was the third `merged` row, on Grok's flat-array shape, until it was removed in September 2026.)
- **`reference`** (MiniMax H3, Kling 3.0 Omni, Seedance 2.5) — a reference RE-ROUTES the request and the frame rides along as a reference image. The mode is forced to reference-to-video so it agrees with the body the builder was going to produce anyway (`minimaxH3Route` / `klingOmniRoute` pick 'reference' the moment a reference is present). Both inputs reach the model, but the frame stops being frame one, which is a real change to what the member gets and is toasted as such.
- **`exclusive`** (the Seedance 2.0 family, the Wan 3.0 family, and the undeclared default) — the provider forbids the pair outright: kie documents first/last-frame and multimodal reference-to-video as "three mutually exclusive scenarios [that] cannot be used simultaneously". The frames win — the frame slot is a deliberate act, not where pictures land by default — and the references are dropped and named, with the way to get them honoured instead. **The drop itself happens in the model's own `buildVideoInput` branch, not here and not in the hosting step**, which is the half that was missing until August 2026: the toast said "rendering from the frames" while the Seedance 2.0 body still carried `reference_image_urls` beside `first_frame_url`, putting a pair the provider forbids on a run the member had committed to. `startPlaygroundVideoTask` hosts references unconditionally on purpose (merged-input models need them), so the builder is the only place left that knows the policy AND sees both groups.
- **`frames-only`** (Seedance 1.5 Pro, Kling 3.0) — no reference input at all. Only reachable by attaching references under one model and switching to another, since Playground hides the ref strip for these.

Two rules hold it together. **The policy lives on the registry entry, never in this file** — `mixedImageInputs` on `ModelEntry`, resolved through `mixedImageInputPolicy`, so adding a model is a registry edit. **Undeclared falls to `exclusive`, not `merged`**, because the costs aren't symmetrical: a wrong `exclusive` drops an input and says so, a wrong `merged` sends a combination the provider rejects — a 400 on a run already paid for. And `startPlaygroundVideoTask` hosts whatever it is handed (references are hosted whenever present, like the audio/video strips): it is transport, the policy call is the caller's, and the `else if` that made it a second unwitting gate is what dropped the references one layer below the code that decided to send them.

**There are no prompt presets or visual styles in Playground** (September 2026, Massimo's call). A `Presets` pill led the prompt toolbar and opened "UGC Prompt Presets & Visual Styles" (fourteen shot presets under the seven looks plus the member's saved styles, each appending a block to the prompt); once the prompt box grew a Voice Profile view with its own presets button, two "Presets" pills a toggle apart read as one control, and the prompt's came off. `presets.ts`, `PresetCard.tsx` and `assets/presets/` went with it — they're in git history if the picker comes back — and `PromptToolbar` lost its `onPresets` slot, which nothing else used. Visual styles still live in B-Roll and Characters.

**A `Voice Profile` field shares the prompt box, and what it holds is appended to the prompt at generate time** (September 2026, `composePrompt.ts`). It is the one part of a UGC video prompt that must NOT change between generations — the same person has to speak in every clip of an ad — so it was being re-pasted two lines under every rewrite and re-selected around every time the prompt changed. A field of its own means the prompt box holds only the shot, and the voice survives Clear, Enhance, Undo and a whole new idea. **Nothing is wrapped around it**: what is sent is the prompt, a blank line, then the text verbatim, because "as if you typed it on the end" is the contract the box is offered under and a label we invented would be a word in the prompt the member never wrote. It is composed onto the run's `prompt` in `handleSubmit` rather than travelling as its own parameter, so the in-flight tile, the history row and Copy prompt all show the string the model was actually given; the empty-prompt backstop still reads `state.prompt`, since a voice with nothing to say in it isn't a generation. **Video only, and never Motion Control** — a voice says nothing about a still or a music track, and that model takes no audio at all. `composePlaygroundPrompt` lives in its own module because a component file that also exports a plain function loses Fast Refresh. **This is what the `videoPrompt` handoff is for, and why it now stashes**: Scripts puts a Send to Playground button on every shot, so the payload arrives over and over, and it must swap the prompt and NOTHING else — the Voice box, the references and the model all survive by construction (`setState` spreads the draft). The mode flip stashes the outgoing tab like `handleModeChange` does and restores the Video tab's own refs; without the stash an image draft was silently overwritten by the incoming prompt, and without the restore you arrived on a video prompt carrying the Image tab's attachments. The stash invariant still holds afterwards — it keeps the NON-active modes, and the live video prompt is written back into it on the way out — so an Image → Video round trip brings the sent shot back, not the draft it replaced.

**It lives INSIDE the prompt box, behind a full-width Prompt / Voice Profile toggle at the top of it** (Massimo's call, September 2026). It shipped as a card of its own under the box (the shared `components/VoiceCard.tsx`, with a persisted fold), and that card cost the tightest column in the app a second set of chrome for a field that is set once and then left alone. As a view of the same box it adds only the toggle's 34px row (the section's floor rises 150 → 184px in video mode to keep the field's own ~4 lines), and the field it switches to gets every pixel the prompt had. **The toggle renders exactly where `composePlaygroundPrompt` sends the profile** — video, never Motion Control. **Which view is showing is session-local, not persisted**: a reload lands on the prompt. From the prompt side, a playground-accent **dot on the Voice Profile segment** (`FilledDot`) says a voice is riding on the end of every run. **A prompt that changes while the voice is showing flips the box back to the prompt** (adjusted during render against the last value): it can only have come from outside the field — Reuse on a history card, Scripts' Send to Playground — and a member must not press Generate on a prompt they never saw land. The voice view has its own two-button footer rather than `PromptToolbar`, whose Enhance / Clear / Undo all act on the prompt: **Voice Presets** and Expand (`ExpandTextModal` titled Voice Profile). It's a plain textarea in the prompt's exact type and inset — no bracket wash and no @-mentions — and there is deliberately **no Clear**: emptying it is select-all-delete, and a destructive control on a set-once field is one misclick from re-pasting a paragraph. The old `voiceOpen` draft key is simply ignored now.

**The voice preset picker is shared with B-Roll** — `VoicePresetPicker`, exported from `components/VoiceCard.tsx`, the card B-Roll's modals still render. **It says "Voice Profile"**: "Voice" is a Voiceovers TTS voice and Omni's attached designed voice, both of which are sound; this is a DESCRIPTION of how the on-camera creator sounds. **A preset row is a NAME, not a paragraph**: fourteen full profiles rendered at once is a wall of prose in which every entry opens "Female in her mid 20s speaking with a…". A row is the accent, who's speaking it, and three trait words (`VoicePreset.traits`); clicking it expands that ONE row to the whole thing plus the button that applies it. `VOICE_PRESETS` (`utils/voicePresets.ts`) are **complete profiles, not templates**, for the same reason the Characters presets fill all 28 fields. The London female entry is Massimo's own reference profile, verbatim.

**Nothing in the References card says "Optional"** (Massimo's call, September 2026). It said it three times at one point — a corner tag on every frame slot, then one pill at the card header, then again on the `Attachments` group — and the word came off all three: everything in this column that isn't marked otherwise is optional, and the card that is unmistakably a pile of extras is the last one that needs telling. What the header pill still carries is Omni's live **`n/7` slot quota** and nothing else, because that is a limit rather than a reassurance — until it landed here it only ever surfaced as an error toast AFTER a member had spent it (the arithmetic is `utils`-side in `omniQuota.ts`, shared with the strip's cap and with the checks OmniInputsSection refuses on, so the three readouts can't drift). Motion Control still gets no pill at all: its two inputs really do gate the run, which is what its red dots are for.

**Every reference slot the active model accepts sits in one `SectionCard` titled References** (August 2026), with a **Clear** on its header once anything is attached (it empties every slot and leaves the prompt alone — that's the member's writing, not a reference). It renders exactly where the slot block already did, so it inherits the model's own capabilities instead of adding a second set of conditionals: Music has no slots and gets no card, nor does a text-only video model (`hasAnyRefSlot`); Motion Control's section takes the card over — but **`isMotionControl` must stay in the card's own gate**, because that model declares `modes: ['motion-control']` and no `supportsReferenceImages`, so `hasAnyRefSlot` is false for it; without the term the card never rendered, its section went with it, and the model became impossible to run at all (a regression shipped in #437 and fixed in the follow-up). Motion Control's three controls are `RefGroup`s of their own (August 2026) — Character Image / Driving Video / Orientation — where they used to be one wrapping row of a slot, a pill and a toggle with **no labels**: both input names lived as captions INSIDE the empty slots and so vanished the moment you filled them. It is also the one place `RefGroup`'s `required` is honest, since the run refuses without both, and the clip's duration ceiling rides on the Driving video label rather than only appearing as an error after the upload; Omni's characters/voices/clip stack under the images; the Seedance clip strips share their row inside it. Image mode's single group still gets the card — one mode reading structurally differently to save 22px is the worse trade. `RefGroup` takes an optional `filled` for the status dot and its label is now small-caps; the **frame slots deliberately have no dot**, since a picture versus a dashed box outshouts a 6px one. **An Omni input with nothing in it is a chip in one shared `Attachments` row; the moment it holds something it opens out into its own labelled group above** (September 2026). Empty, the three of them were three label rows each carrying a single dashed add card — 186px spent offering attachments nobody had attached, in a column whose whole job is the prompt box underneath. Filled, each still gets its heading, its count and its list, so the collapse only ever takes away the state with nothing to show; Voices and Source clip share a row only when BOTH hold something, the same rule the images-beside-clip-strips row follows. The chip row is a **wrapping flex row, never a grid with a breakpoint**: this panel's width doesn't track the viewport's — above `md` it's a fraction of the window, so a small desktop leaves it as narrow as a phone leaves it wide, and a `md:grid-cols-3` truncated "Character" to "Chara…" on a 1000px window while giving a phone the full three across. `flex-1 basis-[112px]` decides per row instead. Every chip carries a helper line (`0/3`, `0/3`, `≤ 10s`) because one of them has to — the clip's ceiling, which a member should meet before the upload rather than as an error after it — and a lone subtitle under one of three identical cards reads as that card being different in kind. **Omni's characters are a 2-column grid of `MediaCard`, matching voices and the source clip** — the three Omni-only inputs read as one list of attachments instead of a tile grid stacked over two card lists. `MediaCard` takes a `thumb` so the character still shows its face in the icon chip's place, and no `accent`: a tint that marks bank-backed rows made one of the three look like a different kind of thing. **Reference images stay 64px `ImageTile` squares with a dashed add tile**, in both Image and Video mode — they were briefly cards too and it was reverted, because on a reference image the PICTURE is the point and a 28px chip beside a filename makes "did I attach the right photo?" the smallest thing on the row. **A frame slot is TWO shapes** (September 2026, `FrameSlot`): EMPTY it's the same 40px `MediaAddCard` every other attach-something control wears, FILLED it opens out to an `aspect-[2/1]` tile — not 16:9, since these sit directly above the prompt box and every pixel there is one it loses; the frame inside is `object-contain`, so the ratio only sets a filled slot's height. An empty slot needs room for one word and a filled one needs room for the picture, and the single 2:1 shape paid the picture's price either way — 124px of dashed box holding a 28px icon, twice over, in the card's normal (empty) state. When one of the pair is filled the grid stretches the other to match, so a lone frame sits beside a full-height drop target rather than a 40px card pinned above an 84px gap.

**The reference-clip strips sit BESIDE the reference images**, stacked, when a model takes both (the Seedance 2 family) — images left, audio over video on the right. The images row is one 64px tile high whether it holds nothing or three, so on that model it was a column of dead space next to an Add tile while the clip cards took a full row of their own underneath. Either kind alone spans the width: the split only pays when there's something to put in the gap, and the tiles want the width when the clips aren't there to claim it (`items-start`, so a filled image grid doesn't stretch the clip column). **That, plus the prompt section's floor coming down from 206px to 150px** (the box's fixed chrome — then a 48px preset row and a 38px toolbar, now the toolbar alone — plus ~4 lines of field), is what puts the prompt box and its toolbar on screen with Seedance 2 selected without scrolling: measured 575px of content in a 493px port before, 493 after. A floor is what the box collapses TO under pressure, not the size it normally renders at — `grow` still hands it every spare pixel the moment the column has one. **Music's two controls sit in the FOOTER with every other mode's** (September 2026, Massimo's call) — model row, then the Instrumental / Lyrics `SegmentedToggle` at `h-12` (the `size='lg'` chip height the other modes' output settings run at, so the band is the same three rows in every mode), then Generate. They sat ABOVE the prompt box for a stint on the reasoning that neither is an output setting the way resolution and duration are; what that cost is the reading order, since the panel's subject is the box you type in and two full-width controls stood 110px of chrome between it and the mode tabs. Every mode now settles what it is making directly over the button that makes it. The toggle is a real `SegmentedToggle` at the same height as B-Roll's Voiceover / Dialogue pair — the same question asked of a generation — which is what added the `playground` accent to `SegmentedToggle`; its second label is **Lyrics**, not "With lyrics", since the pair is read as one question and the preposition only appears on one side of it. The batch stepper stays off this row: Suno returns a pair of tracks per call. **Where that stepper lives is a per-mode answer** (September 2026, Massimo's call): VIDEO keeps it beside the model trigger at `size='xl'`, because that mode's chip row already carries resolution, aspect, duration and sometimes audio and a fifth control would wrap it; IMAGE moves it into the chip row at `size='lg'`, to the RIGHT of the aspect ratio, where it sits among the other properties of the thing being made rather than beside the model that makes it — that row holds two chips in image mode, so it has the space. `stacked` in both, since the number is what is read and the word is what it counts. `hasOutputSettings` is unconditional for image mode as a result: a model that declares no image constraints still has a count to show, and skipping the row would take the stepper with it. **The scrolling body column is `min-h-full`, never `h-full`.** Both make it at least the port, so the prompt box keeps a ceiling to shrink against and `grow` still fills a short panel — but `h-full` also caps it AT the port, so the scroller never learns its content is taller. Pick a model with a lot of inputs (Seedance 2: two frame slots, a ref strip, and both clip strips) and the References card alone outgrew the port: the prompt box was pushed past the bottom edge and clipped there with no scrollbar to recover it, while the wheel fell through to the page behind. **The footer stack runs on the app's shared control sizes** (August 2026): the model trigger is the 58px picker row (`ModelPicker row`, the same geometry as `ScriptModelRow` and the bank/style rows in Scripts and B-Roll) with the batch stepper `shrink-0` beside it at the matching `size='xl'`, the constraint pills under it are `size='lg'` (48px, the Characters generate bar's), and everything in the column sits 8px apart. `row` exists alongside `large` because `large` is for a trigger that SHARES a row with its chips — Characters' bar puts both at 48 — while this one owns its row. **Several clips are zipped by picking them ON the grid, never in a modal that lists them again** (September 2026, Massimo's call). The Download-clips *picker* was removed here in August 2026 and stays removed — B-Roll keeps one because its list is ONE storyboard, a finite set of takes exported together, while this list is every clip the member has ever made — but the underlying want survived it, and the answer is that the wall of tiles you are already scrolling IS the picker. **The history header is PINNED OVER the grid and frosted**, the shape B-Roll's storyboard bar already has (`app-backdrop-frost`, `absolute` not `sticky` — this bar never scrolls away; September 2026, Massimo's call): the tiles pass under it instead of stopping at it, so the wall of stills reads as one surface running the height of the pane. The scroller's `pt-[69px]` is the bar's 57px plus the 12px the content already stood off by — change one and change the other. A **Download Clips** pill in the history header (Video tab, grid view, and only once there's a clip to pick) turns every video tile into its own checkbox — it names the outcome, not the gesture, because "Select" alone said nothing about what the selection was for: the tile toggles instead of opening the preview, an unselected one dims to 60% and lifts back to full on hover, and the tick takes the top-RIGHT corner the `TileActionStack` vacates. **The transport stays live while you pick** — play, pause and mute are exactly what you reach for deciding which take to keep, and both handlers already `stopPropagation`, so pressing one never ticks the tile. The gesture takes over the panel's own 57px header rather than raising a band under the scroll port, and it carries **no "N of M selected" tally**: the count rides on the Download button, and a second copy of it beside Select All is what clipped that link at panel width (this pane's width doesn't track the viewport's, so no breakpoint fixes it). The Grid/List toggle stands down while picking, for the reason the project opener does — flipping the view drops the selection — and at 375px the bar can't hold it beside Select All, Download and Cancel anyway. Nothing is preselected — this list runs back weeks. Zipping goes through the shared `utils/downloadZip`, one file per clip named `<index>-<prompt slug>` in the order the grid showed them, into `playground-clips-<YYYY-MM-DD>.zip`; a success clears the selection and leaves select mode. `zipClips` sits at MODULE scope on purpose — a try/catch in the component body makes the React Compiler skip the whole component, and this is the grid that must not re-render while the member types beside it. `components/ClipDownloadModal` stays where it is for B-Roll's two modes. **Its tiles only hold their media while they're near the scroll window** (`hooks/useNearViewport`, root = the scroller): a member with 60 clips was mounting 60 `<video>`s in the grid, which is 60 blob reads out of IndexedDB and far more decoders than a browser hands out — past its budget the extra elements never paint, so the tab stalled on a black grid. **Only the CLIPS release, though** — `release: true` on the video tile, the list row's video branch and `ClipDownloadModal`, all three of which size their FRAME rather than let the media do it. A still keeps whatever it loaded: its tile is sized by the picture and its placeholder by the declared aspect ratio, so a still that released would change height above the viewport and drag the grid under the pointer (reported twice, September 2026 — the second time against Characters, after a revert took the default away). See `hooks/useNearViewport.ts`. **What a tile RENDERS is the asset's thumbnail, never the original** (September 2026): a still through `useAssetThumb`, a clip's first frame through `useAssetPoster` — the poster is what a released video tile keeps showing and what the returning `<video>` wears until its first frame decodes, so releasing is invisible. The preview modal stays on the original. See `utils/mediaThumbs.ts` and `docs/performance.md`. **A list row names the model that made it** (`components/ModelPill`, `chrome` variant), on its own line above the meta pills — the same reading order Characters' list row uses, so a row looks the same across the two apps. **Under a 560px list it stacks, media over details** (`@container/list`, shared with the in-flight row): side by side at a phone's width the details were a ~90px strip whose action line the card's clip cut off. List only in the history itself: the grid is a wall of pictures and a caption on each is exactly the chrome that shape exists to avoid. **The preview modal names it too** (`media` variant, above the prompt), for both stills and clips and whichever view they were opened from — the modal is where an output is actually judged, and it is the one surface that can answer "which model made this?" for a grid tile that deliberately doesn't say. It's `media` rather than `chrome` because that modal is a literal black overlay in both themes, like every other label in it, and it takes `shrink-0`: the side column overflows on a short viewport and a flex child with no floor is squashed — measured 5px tall against its natural 19px. **Every history card carries a Reuse (`CornerDownLeft`) button beside Copy prompt** (September 2026) — grid tile, list row and preview modal, for all three kinds — putting that generation's prompt back in the box and REPLACING what's there. On a grid tile and a list row the pair sits behind the ⋮ (`TileMenuButton`, spelled out as Copy Prompt / Reuse Prompt): the still's stack had six circles against the app-wide ceiling of four, so it runs Download · Save · Animate · Delete · ⋮ — Characters' split, with Animate keeping its circle as this app's one-click loop — and a clip's runs Download · Delete · ⋮ so the pair is in one place on every tile of the wall. It sits right after Copy prompt because the two are siblings: one hands the words to the clipboard, the other hands them straight back to the field, which is what you wanted every time you copied one. The glyph is the **return** key (Massimo's call, September 2026) — it was a plain left arrow, which is the back-button mark this app uses for going back a screen; a return arrow says the words are being put INTO a field, which is the thing that happens. Characters' Reuse wears it too, so one action reads the same in both apps. `handleReusePrompt` swaps the prompt and **nothing else** — the Voice box, the references and the model all survive, the same contract the `videoPrompt` handoff runs on — and it takes the card's own MODE, flipping the tab through the same `promptStash` a manual switch uses when the two differ. That argument is not optional: the grid is no longer sliced by tab (see Projects below), so the card you press Reuse on is routinely not the tab you are standing in, and landing a video prompt in the Image box hands it to a model that can't make the thing it describes. `PromptPanel`'s own effect snaps the model to the new tab, so nothing in the handler has to. It flips the phone's pane to `prompt` (the grid is the pane you pressed it from) and deliberately raises **no toast**: the box visibly changes, which is better feedback than a line of copy. It genuinely replaces, with no undo of its own — `PromptPanel`'s stack only tracks changes made inside the box — which is what the button says it does and how every other prompt handoff into this app already behaves. `useCallback` is not optional on the handler: the grid is `memo`'d against hundreds of rows and a fresh identity per render re-renders the whole list on every keystroke.

## Projects

**The history panel is sliced by PROJECT, never by the mode tab** (Massimo's call, September 2026). It used to filter on `state.mode`, so flipping Image → Video swapped the whole right-hand pane for a different list. That cut is wrong for what this app is used for: one piece of work is the stills AND the clips AND the track for an ad, and a member making one wants them in one place. A project is the cut that replaced it — the member's own grouping, the way Google Flow's projects are — and **flipping tabs now changes nothing on the right at all**. Three things fell out of the unslicing and none of them is optional: **Reuse takes the card's mode** (above), because the card is routinely not the tab you're standing in; **`musicOnly` is a question about the visible list**, not about a tab; and the **empty state is a STATE of the grid rather than an early return**, because the early return took the header with it and, with the project opener living up there, making a project meant landing in it empty with no control left on screen to get back out. **That empty state sits on the graph-paper canvas** (September 2026, Massimo's call): `CanvasFrame` wraps the scroll port in `GridCanvas` whenever there are no entries and no in-flight tiles, and drops it the moment the first tile lands — the rule Scripts and B-Roll already follow, and this was the one empty state in the app standing on bare panel, which read as the Playground being a different KIND of surface rather than the same stage before its first run. The pinned header is `z-20`, so the frame's positioned column still passes under it; both branches keep one flex shape, so the grid arriving never reflows the tiles.

**The projects list is B-Roll's history rail, for projects** (`components/ProjectRail.tsx`) — the same 280px column popping out of the pane's right edge, the same `h-[57px]` band led by a `RailNewButton` (**New Project**, playground accent, one click — `confirm` is gone from that component entirely; see `components/RailNewButton`), the same slide-in arrival, `useHistoryRailOpen` so it ships shut, and `components/RailOverlay` so it is dismissed by clicking away from it (picking a project hands the pane back, since the rail covers the grid). **A project is a CARD under a DAY PILL, not a row** — B-Roll's `HistoryCard` geometry down to the `aspect-[16/10]` cover mosaic, the top scrim, the `TileActionStack` and the centred caption, bucketed by `groupByDay` under the same `DayPill` its rail uses — so a project reads as what is IN it rather than as a name in a list, and a week of them reads as a week. What dates a project is the last time it was GENERATED INTO, falling back to when it was made: a folder you worked in this morning belongs under Today whenever you happened to create it, and an empty one has nothing else to be dated by. **All Projects sits OUTSIDE the pills**, above them — it is everything in every project plus everything never filed under one, so it belongs to every day and to none. It was named All Generations under the `Layers` stack until September 2026, when it became **All Projects** with a closed `Folder` (Massimo's call) — the open `FolderOpen` marks a single project, so the two read as one family. Two lists of the same kind of thing in two apps should not be a rail in one and a dropdown in the other; a dropdown is what this shipped as for half a day.

**The opener in the history header is NOT `HistoryRailToggle`**, and the difference is the one thing this bar has to say that B-Roll's doesn't: which project you are looking at. Over there the storyboard on screen IS the open session, so a button reading "History" loses nothing; here the grid under a project and the grid under All Projects are both a wall of tiles and nothing else on the pane tells them apart. So the opener carries the NAME — one control that answers "where am I" and pops the rail out in the same press — on the same ring and wash at the same `h-[38px]`, wearing `PanelRightOpen` rather than a chevron. It is what made room on this bar a real problem at 375px: **Download Clips drops its label and the Grid/List toggle drops both of its** on a bar under 520px — a container query on the bar (`@container/bar`), since this pane is as narrow on an 820px window as on a phone and a `md` cut left the labels up there and squeezed the name to "A…" — per the mobile rule that a bar which won't fit shortens a label rather than shrinking a control again — the project name is the label that has to survive, and those two icons are unambiguous (the toggle's segments take `ariaLabel`, and the labels are `hidden` rather than `sr-only`, because an `sr-only` span is still a flex child and leaves the glyph half a gap left of centre).

**A generation is stamped with the project that was active when Generate was pressed, not when it landed.** `projectId` rides on the persisted `InFlightGen` and is read back by `playgroundRunner.finish`, so a clip that took twenty minutes — or a whole reload — is still filed under the piece of work it was started for. The Recording Mode fakes and the replay-loop tile carry it too, or the loop tile vanishes the moment a project is open. **Deleting a project deletes the FOLDER and never what is in it**: the history rows keep an id that no longer resolves, which reads as unfiled, so they come back under All Projects rather than disappearing with the name — see the `projects` bullet in `src/lib/CLAUDE.md` for why the field isn't swept. `summariseProjects` (`projectSummary.ts`, its own module because a component file that also exports a plain function loses Fast Refresh) builds every card's covers, tally and timestamp in ONE pass over the list the grid already has; the covers lead with stills because a still is an `<img>` off a thumbnail while a clip's face is a poster that may still be being made.


**A music track is played by the app, never by the browser** (September 2026), and since the same month it is a ROW, not a tile. Every music surface here rendered a native `<audio controls>` first — the one control in the app that ignores the theme outright, its own grey slab and its own overflow menu, three of them stacked down a panel whose every other tile is custom chrome. They wear **Voiceovers' History card** instead, the whole shape and not just its transport (Massimo's call): a play disc on the left, the title over `1h ago · 0:32 · Instrumental`, the prompt under it, and `AudioScrubber` opening on play and closing when the clip ends. It was a tall gradient cover tile in the four-up grid with a waveform under it, and both halves cost more than they paid — the artwork is not a picture of anything (a seeded gradient with the title written across it), so a grid of tracks was a wall of coloured rectangles saying less than a line of text, and it pushed the prompt (the only thing naming the track) two thirds of the way down the pane. The cover survives at avatar size AS the play button, the way the voice avatar does over there, so a track is still recognised by its colour. The waveform went in the same pass and `components/Waveform.tsx` was deleted with it — see the audio idiom in the root file for what that costs to bring back. **A track has no thumbnail, so this row is the grid view AND the list view**; in the grid a day's tracks sit together UNDER its wall of tiles rather than in time order between them, where each full-width row cut the wall in two (the dense grid backfills holes, so it had never kept strict time order among the tiles anyway); the Grid/List switch and the card-size slider don't render while tracks are ALL that's on screen, since neither has anything left to change. That used to be a tab test (`filterMode === 'music'`) and is now a question about the visible list (`entries.every(e => e.kind === 'music')`) — the same question, asked the only way it still can be now that the panel isn't sliced by tab. Actions moved off the artwork into a hover cluster on the row (Voiceovers' 28px ghost buttons, `TileDeleteButton variant='chrome' size='sm'` closing it) and stay put while the track is loaded — the row you are listening to is the row you reach for. `hooks/useAudioPlayback.ts` is the transport and is **per row**, not per list: the element is built on the first press (a history of dozens of tracks has no business opening dozens of media elements), the row then holds it so a paused track keeps its scrubber, and the shared slot still pauses whoever was playing. Voiceovers' History keeps its own list-level copy of that logic, which predates the hook.


**The list row's `<video>` carries `#t=0.1` on its src**, and it is load-bearing: with `preload="metadata"` Safari fetches duration and dimensions but decodes no frame, so the element painted as an empty black box — the clip was there and invisible until you pressed play, while the grid tiles (which autoplay muted on hover) looked fine. The media fragment forces a seek to 0.1s and with it a decode. Same fix as B-Roll's history `CoverTile`; don't drop it from either.
